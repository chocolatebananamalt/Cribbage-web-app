# Result MRP membership reporting, 2026-11-13

Source: current owner delegation, including corrected website/override/nonmember policy. This supersedes incompatible reporting-gate language in earlier candidate notes, without changing the old unmounted eligibility helper.

Connect the existing result-based proposed report to its enrolled roster and protected manual-review history. Reuse the established normal-client read RPC, without new privileges or browser-supplied identity/status. Only a unique enrolled verification ID plus matching display label may associate a roster entry. Invalid or absent history stays unavailable. Stable annotations are exported with their head IDs/digests and source timestamp; a membership mismatch between reads drops annotations, while result-source drift and actor/session changes retain the original rejection behavior.

Optional annotation work has a total 1500 ms budget per capture, reads only result qualifiers, and uses at most four concurrent review reads. Timeout returns no annotation and prevents further dispatch; existing in-flight read RPCs may finish but cannot alter the returned report. A current website-error correction disputes a nonmember observation, never authorizes an award; withdrawal restores its cap. The helper does not manufacture numbers, verify active membership, consult lifetime totals, submit reports or record official awards.

CSV extends the existing proposed-mrp report with reference status, hypothetical/app-proposed basis, reporting permission, unresolved override audit, zero nonmember maximum, and a separate unknown official ACC-approved amount. `sourceDigest` represents the inputs actually used for that report: it includes stable annotations and excludes dropped unstable annotations. Matching double reads remain explicitly non-atomic.

Runtime prerequisites remain unchanged: resultBasedMrpEnabledV1 and manual review routes are default off. The manual-review SQL proposal currently revokes every execution role and needs a separately reviewed enabled provider/ACL installation before normal-client reads can succeed. This patch does not enable it or grant access. Missing/denied review RPCs remain optional unavailable annotations. Mixed/manual proposed report paths are separate and unchanged. No new UI requires browser acceptance in this slice; signed-in provider/backend acceptance remains unverified.

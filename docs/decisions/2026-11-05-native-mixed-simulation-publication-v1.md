# Simulation-aware roster, draw and schedule: source-only design

## Scope and acceptance

Parent authorized local source-only integration for the 18-player rehearsal.
All mutation paths remain private/default-disabled. No new mixed database
fixture, SQL execution, permission grant, hosted data, publication or money
movement is authorized. Existing setup/device/historical records are not used
as a test target. This does not authorize applying the prior opt-in consent RPC.

The coherent source path is sealed-current rehearsal readiness, explicit
`sim_ready` identity projection, Director-reviewed immutable plan, one durable
random-draw attempt, explicit review, then atomic simulation seating/schedule
publication with real canonical IDs and mandatory test provenance. It must not
fabricate ordinary `checked_in`, QR/desk, payment or physical-presence evidence.
Normal Start, final scoring/Finance and public access remain outside this slice.

## Reuse and independent simulation boundary

Reuse the existing 18-circle random sampler, unbiased bounded integer helper,
configuration validator and independently reviewed A18 candidate/movement
validator. Do not feed `sim_ready` through the old ordinary checked-in source
predicate. A new test source must re-read exact current intent/funding/readiness,
latest six grants, twelve unlinked fictional identities and current preparing/
reviewing roles, plus the active open Standard-12 Main and closed registration.
No accepted draw, permanent IDs, schedule, Start or prior scoring may exist.

V1 supports only one literal table A with eighteen odd/even opposite positions,
nine complete facing pairs and one anchor at A-1. It does not certify a room,
invent multi-anchor movement, or imply all six people meet each other. Director
inputs preserve stationary-request decisions and explicit verified per-round
pair constraints, with their source references. These are declared inputs,
not inference from names or a new universal ACC family rule. Existing technical
limits (36 constraints, bounded attempts up to 256) are not ACC policy limits.

One **committed draw attempt**, including a bounded no-candidate result, prevents
new operation IDs from silently resampling. Exact lost-response retry returns
the retained result. Uncommitted transaction failure does not prove exactly-once
physical entropy: no candidate/receipt committed in that case. No candidate is
proof of infeasibility or permission to silently redraw. Config/review changes
after a retained attempt require an explicit new-trial path, not a mutable map.

## Publication and immutable identity

The ordinary writers require actual check-in and must remain unchanged. A new
private simulation writer has its own explicit predicates and revalidates the
whole native graph rather than calling an ordinary writer with forged guards.
It creates actual native operation receipts, initial publication/18 unique
assignments, twelve rounds, 108 canonical games and schedule links together.
Fixed Tournament IDs come from the reviewed first-round positions and never
change with subsequent current seats. No ACC member number is a Tournament ID.
No future canonical UUID or permanent ID is supplied by the client or local
planner; actual canonical UUIDs are allocated by the committing writer.

Immutable simulation sidecars bind the actor/operation/request, backend PID and
transaction, exact readiness seal/digest, plan/draw/review, native receipts,
publication IDs, fixed roster/participant mapping and all game IDs/sides/seats.
Mandatory source guards plus postcondition/rollback proof must reject missing,
foreign or inconsistent sidecars. Retain native FK/uniqueness/immutability,
registration/lifecycle, anchor/family and 108-graph conditions. No partial native
publication can survive child failure.

The schedule source is truthfully `native_mixed_simulation_v1`, not
`director_csv` or `director_entry`. A proposed CHECK extension allows only this
additional explicit discriminator; it is not applied now. The ordinary reader
and DTO must not quietly relabel it. This slice instead defines a private test
source and an unconnected private adapter. General app/provider/UI dispatch
remains a separate integration/acceptance gate.

## Consent, revocation and recovery

New plan, draw, review, publication and current-source reads require latest
consent and current roles under source locks. A revoked or stale readiness seal
blocks the next new operation. An exact owned receipt may still be recovered
after later revocation if the caller retains permission; that is historical
evidence, with `currentSourceVerified:false`, not current readiness or new-write
authority. Do not erase accepted draws, IDs, receipts or prior reviewed records.
Downstream generated scoring and rehearsal Start must eventually consume the
same current consent state; they are not enabled by a schedule publication.

## Pure local adapters

`native-mixed-seating-plan-v1.ts` derives a non-authorizing `sim_ready` roster
from supplied sealed readiness and explicit lifecycle/configuration. It reuses
the existing local planner and one-table movement, rejects stale/revoked data
before RNG, makes retained draws/IDs read-only, preserves request/constraint
inputs and detects observed input mutation during sampling. Its A-IDs are
provisional candidate labels. Injected test RNG is not database entropy.

`native-mixed-published-schedule-v1.ts` recognizes only the private simulation
source. It compares supplied publication claims with retained historical plan,
draw/review and actual supplied UUID pins, checks eighteen fixed mappings and
all 108 side/round/seat tuples, and rejects ordinary source methods. It does not
generate IDs or mutate anything. A valid borrowed UUID/digest cannot be detected
from shape alone; database proof, publication/write/Start, physical room and
money authority remain false. These adapters have no provider/API/page route.

## Exact proof and approval gates

Source/unit/static checks and independent review are necessary but not SQL
acceptance. A separately approved disposable database must prove syntax and
catalog/ACL/forced-RLS/constraint behavior, authenticated subject and current
role boundaries, positive actual native row readback and exact all-108 mapping,
unbiased sampler behavior, bounded-failure retention, same/competing requests,
manual-writer collisions, revocation/source drift, lost response/replay,
cross-domain nonce conflicts, injected child failure/rollback, deferred guards,
UTC/cross-session hashes and owned cleanup. No such fixture is created here.

Before any hosted trial, freeze the exact proposal/grant manifest, verify the
staging target and a fresh recoverable database backup through isolated restore,
preserve authorized fixture baselines, and obtain separate explicit scope for
schema changes and permanent IDs/schedule in the named test tournament. No
production, new accounts/roles, invitations, optional consent grant or real
financial records are included implicitly. An app rollback cannot undo DB rows
or the new source discriminator. Current source archives are not DB recovery.

The private core has no normal Director transport/execute entrypoint. Preparing
and reviewing a least-privilege transport is implementation work still missing;
it must bind a verified test project, named tournament/event, allowed actual
actors and expiry. A TEST ONLY name alone is not deployment authorization.
Applying any execute permission needs separate approval. Owner-only local SQL
tests cannot be labeled real signed-in provider acceptance.

Actual provider/HTTP/UI acceptance, personally accepted officials, six actual
signed-in subjects, room/anchor walkthrough, explicit test-rehearsal Start and
mixed offline/score/Finance/final recipient integration are still required.
Keep source disabled and publication on HOLD until the relevant gates pass.

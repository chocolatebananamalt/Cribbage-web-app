# Native mixed funding journal: source-only design

## Acceptance and boundary

The parent authorized local source-only work on the native-compatible simulated
funding/provenance gap, with source/unit tests and independent review. No new
database fixture, SQL execution, hosted read/write, invitation or publication is
authorized. The previous approved 18-player runtime remains historical evidence
for its frozen legacy path, not acceptance of these new sources.

This slice must derive the Main entry amount and eighteen identities from the
latest retained native admission intent and active native settings, without a
legacy prize declaration. Simulated funding must never be reported as cash,
verified bank evidence, actual disbursement or ordinary native V2 source data.
An immutable quarantine marker must exist before the first simulated record.
Unknown, stale, cross-event, ambiguous or incomplete data blocks; it is not zero.
History remains immutable; no refund or legacy-award conversion is introduced.

## Separate journal rather than fictional ordinary receipts

Use private, forced-RLS, default-disabled proposal tables for the native mixed
scope, operation/recovery records, simulated obligations and receipts, and their
atomic context/provenance. Scope enrollment binds the current intent ID,
version, source digest, immutable identity/mode/profile/link capture and native
operational settings. The amount is derived from the pinned setup, never from
caller input or a fixed historical $30 assumption. A source is complete only
when all eighteen identities have their exact entry obligation and simulated
receipt. There is no refund, zero-eligible pool rule or payout writer here.

The native mixed intent and funding scope must be recognized by the ordinary
ledger's existing mixed-domain exclusion. This extends quarantine, not access.
Do not omit mixed markers to obtain native V2 ownership. Do not insert a legacy
prize declaration or copy a legacy final liability. Preserve the legacy paths
and their historical records unchanged.

This first journal is Main-entry-only. Optional Q-Pool/Side Pool memberships,
allocations, costs, sanctioning assessments, additional income and final awards
remain separate source contracts. Their absence is explicitly unavailable, not
an assertion that their funds or liabilities are zero. No tournament cost may
silently reduce a voluntary pool.

## Pure observation contract

`native-mixed-funding-observation-v1.ts` validates a complete supplied source
against separately retained scope and identity pins. It checks all eighteen
distinct owners and operations, six linked Digital identities, twelve unlinked
Paper identities, exact currency/method/amounts, totals and all false authority
flags. The private dependency-injected reader checks existing Director
access before reads, rechecks the actor/roles, owns its snapshots
and compares two complete source loads. Its access contract is Director-only,
matching the private SQL producer; it does not grant co-director access.
No provider, API or page invokes it.

The output is `simulation-observation`, never ordinary V2 `sources_available`.
`databaseProvenanceVerified`, Finance availability, paid-check-in, bank/payment,
refund, payout and finalization authority remain false. DTO shape and matching
double reads cannot prove database ownership, a current hash, audit coverage,
atomicity or a source lease. The tests deliberately demonstrate this limit.

## Candidate admission dispatch and timestamp stability

A separate proposal replaces only the unexecuted admission candidate's
financial seal helper with the new journal source; no legacy financial function
or historical record is replaced. It retains both disabled gates, latest intent
pins, pre-scoring checks and independently current 18-player mixed enrollment,
fixture hash and canonical game/side/version bindings. No legacy scope fallback
is allowed. This removes the legacy prize-declaration prerequisite at the source
layer, without making normal Start or Finance available.

Timestamp-bearing JSON and row hashes must use function-level UTC consistently
in the new writers, source/binding helpers and candidate admission capture
functions. Different caller session time zones must not make unchanged new rows
stale. Do not rewrite or silently normalize old stored captures; mismatched old
history stays blocked. Cross-session time-zone behavior needs runtime proof.

## Normal attendance and Start are still blocked

The current paid predicate in migration 0207 reads ordinary obligations and
receipts. Desk and QR attendance call it; attendance closure and Start require
those event attendance records. The current attendance source constraint is
`qr | desk`. This separate journal intentionally writes neither ordinary
payments nor a fictional QR/desk attendance record. Therefore it cannot, on its
own, make paid check-in, attendance closure or normal Start work.

A future coherent bridge needs either quarantined, atomically annotated
ordinary obligation/receipt evidence plus truthful test-attendance provenance,
or a separately reviewed explicit simulated attendance source and Start path.
Neither is a one-function bypass. Do not weaken the normal paid predicate,
claim a human attended, or directly mark participants checked in to evade it.
Roster check-in used by a draw is not event attendance.

## Exact verification still required

After implementation and source review, a separately approved disposable
database must prove installation and ACL/catalog behavior, latest intent/native
settings binding, empty-history enrollment, conservative quarantine before any
write, derived amounts and immutable provenance, role revocation, same/competing
operation races, exact replay/reconciliation, child-failure rollback and stale
source rejection. Inspect persisted rows and actual function grants, not only
responses. Preserve and verify removal of the owned test database.

No positive normal Start or native Finance claim is possible without the missing
attendance and source/recipient integration. Further provider acceptance must
exercise actual signed-in, personally accepted roles and independent nonself
review. Digital confirmations remain identity-bound; generated paper evidence
must not masquerade as genuine digital or physical-play attestation.

Keep this path private and disabled. Do not stage it alone. A future release
needs a complete reviewed dependency/grant manifest, fresh verified database
recovery through isolated restore, authorized fixture baselines, exact test-only
scope and separate publication approval. A local source ZIP is not DB recovery.

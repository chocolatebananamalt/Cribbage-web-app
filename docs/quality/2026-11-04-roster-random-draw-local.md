## Implementation boundary
`database/proposals/random-seating-draw-v1.sql` adds private immutable operation/outcome/plan/draw records with role-checked service-only RPCs and no direct user table grants. An accepted revision captures authoritative roster evidence and director-declared decisions. Draws use database cryptographic rejection sampling and Fisher–Yates; client randomness never selects players. One transaction reserves actor/operation, checks source/config/prior draw, records candidate and audit and commits its receipt. Caught failures and exhausted search are durable outcomes. A database crash before transaction commit exposes no candidate and is not a claim of exactly-once physical entropy sampling.

The new API/page is default-off and restricted to development/test loopback origins AND an explicitly configured loopback backend URL/port, before constructing auth/database clients. The production adapter uses existing verified subject and server-only private RPC access. No credentials/role grants are created. The browser retains only actor/tournament scoped operation/config in the existing recovery coordinator namespace, not the anonymous storage exception. Full immutable GET request body (phase, operation, reason, prior-draw and config) is compared before clearing retained work. Stale stored bytes stop a retry before any request.

Director UI shows actual local checked-in names, per-table chair controls, facing pairs, explicit stationary requests/decisions, pair-round exclusions, saved revision/currentness, candidate-only proposed IDs and recovery controls. It does not auto-import family policy or silently discard a request. Old candidates are historical after source/config changes. No table/seat publication or physical walking directions are offered.

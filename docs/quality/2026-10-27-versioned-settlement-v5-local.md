## Implemented contract

* Canonical MRP is derived from exact tagged legacy-v2 or v3 result/qualification bindings. V3 revalidates its four-qualifier, three-series seeded topology; legacy supports complete power-of-two/no-bye evidence, 4–256 qualifiers, and the existing supported Main/Consolation game counts. Champion credit is derived from bracket depth; unique legacy third/fourth order is not an ACC elimination distinction. Bye, incomplete, tied or contradictory legacy evidence is explicitly blocked pending typed correction. Raw historic rows are unchanged.
* Private shared SQL validation is used by the automatic legacy reader, legacy MRP-claim inserts, legacy finalization inserts, and the new draft/finalizer. Older direct/manual entry points cannot store incorrect canonical claims or bypass final evidence checks. Safe legacy grants remain intact. Event-scoped triggers prevent opposite playoff write domains and prevent old settlement writes after v5 adoption.
* New immutable draft/final tables bind exactly one legacy or v3 result with scoped foreign keys. First transitions retain explicit legacy predecessor IDs; later versions retain same-family supersession. Financial prize amounts and optional order are explicit director claims, independent of elimination cohorts. No payout/tie policy is generated.
* New service-only workspace, draft, finalization and reconciliation RPCs authorize the current director/co-director, serialize actor/operation and event writes, preserve exact accepted/rejected replay, and record conflicts with attempted hash, reason and same-tournament prior receipt. Only reviewed controlled failures become durable rejection receipts. Unexpected faults propagate, preventing a poisoned operation ID.
* A historical v4 wrapper now delegates an existing deterministic child operation to its original v3 receipt before applying today's corrected calculator. Historical accepted 76-point claims replay unchanged; new requests must use the corrected 97-point champion claim. No historical claim is rewritten.
* The assessment comes only from the immutable event-start sanctioning snapshot. Positive assessments require explicit binding to a current same-tournament recorded expense, adequate amount and conserved/allocated ledger evidence. No receipt, expense or payment is automatically created. The existing 4,800-cent fictional assessment remains **unfunded**.
* Finalization rechecks latest qualification/result, active event, recorded and current cross-check conditions, disputes, canonical evidence, exact ledger snapshot, conservation and cross-event allocations. Q Pool claims and automatic payouts are unsupported in v5; configured positive Q Pool or omitted award obligations block finalization. Ordinary legacy workflows remain available where their evidence is valid.

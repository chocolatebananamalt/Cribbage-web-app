# V23 recorded identity at check-in — local, unpublished

## Outcome and scope

Preserved V22 base 8040f92f2355d6161b937ab7a2bcc755652846f0. Inspection found that the real Seating page rendered only legacy roster displayName even when an existing adopted identity had a persisted prefix, middle name, suffix or local differentiating label. This slice adds an explicit read-only Review recorded identity beside each check-in row. It does not create/adopt/correct people or establish that the person at the desk is the recorded person.

Acceptance: under the existing adoption availability gate, the current primary Director can explicitly read the profile bound to that exact roster ID; two preaccepted people with identical legal name/address retain separate recorded distinctions. Null, foreign, wrong-row, incomplete and stale responses must not select the namesake. Review sends only GET and never check-in, payment, allocation or recovery writes. Existing legacy operation behavior remains intact if the optional identity scope is unavailable.

## Implementation

The actual Seating page resolves an optional verified Director/session scope only under adoptionEnabledV8. Resolution failures are caught within that optional branch, preserving original tournament access/workspace behavior. Co-directors receive no new access. The existing adoption profile endpoint, server handler, capability pins and provider are reused without changes. No new flag, API, RPC, SQL, grant or Auth contract is introduced.

The row mounts CheckInRecordedIdentityV23 keyed by actor/session/tournament/roster ID. Reads are explicit, no-store and abortable. Auth events invalidate displayed/pending results without inspecting token/session payloads. Unmount, gate removal and committed actor round trips discard old responses. Strict readProfileV8 binding precedes a display whitelist: persisted distinguished name, existing local reference, nonmember status and incomplete-address warning. Internal UUIDs, full address and private notes are not displayed; DOB is not collected. Actual issued ZZ remains nonmember; a Temporary ID is only a local existing label, never generated by this feature or exported.

Check-in selections, request bodies, fees/payments, registration closure, seating assignments, search, publication and recovery storage/actions are unchanged. Existing row disabling also disables its optional read button; this is currently a pre-closure check-in affordance, not a new post-closure directory or identity-aware search. Legacy name headings remain visible alongside the recorded distinction. No automatic match/merge or mandatory identity approval policy is added.

# Event-Bound MRP Evidence Foundation

Local source only, default-off, no mounted route, SQL or point writer.

Acceptance: normal authenticated primary Director identity/session is checked before, between and after two captures. Exact captures bind event/date, roster, membership and canonical result revisions. Changed source, role, session or gate conceals evidence. Retained snapshots must exactly match fresh collection before Director review, and pending members prevent readiness. Adapter scope mutation must not change the original target.

The protected adapter contract requires independently established event-specific identity/date authority. Existing manual journal notes, missing roster entries and public current lookup are not such authority and are not wired here. Full event-date coverage is a conservative hold, not a new rule for ambiguous membership changes during an event. No renewal-grace arithmetic. Points are dated on the last day, consistent with cached ACC Policy Manual Ch6 VI.A.2–3. Original observations, reasons, corrections and withdrawal evidence remain in the private retained capture; no new public disclosure.

Coverage is explicitly supported canonical playoff qualifiers only. Existing canonical validation still blocks unsupported results, byes or formats; this is not a full-event export. Unknown membership leaves awarded=null, confirmed inactive/nonmember projects zero, and accepted event-specific correction retains original evidence. Performance arithmetic remains unchanged.

Verification: six focused collector/snapshot tests and 31 existing membership tests passed; TypeScript and focused ESLint pass. Review found a mutable second-read scope alias and final-await gate gap; both corrected with a regression. No database/provider/browser acceptance, official finalization, full-suite build or audit claimed.

Remaining implementation: protected date-specific evidence authority/store adapter, real event/identity mapping, authenticated audit acceptance and transactional immutable MRP writer that locks/recollects source before saving. Matching double reads are explicitly not atomic. Every returned value has mrpWritten=false and finalizationAuthorized=false. No hosted operations, denied-operation retry or fixture creation.

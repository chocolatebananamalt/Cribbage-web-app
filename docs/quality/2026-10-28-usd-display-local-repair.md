# USD display and settlement guidance — local repair

Owner instruction 2026-10-28: monetary amounts must display in dollars, e.g. $24.00, rather than 2400 USD cents. Scope is presentation and exact input conversion, with no rescaling of stored records or changes to payout policy, authorization, finalization guards or hosted data.

## Acceptance and implementation

- V5 settlement current ledger and saved snapshot, assessment, individual expense evidence/dropdown, calculated awards and remainder use dollar currency formatting. Editable allocations and prize amounts use USD dollar strings, not minor-unit numbers. Existing correctly dollar-formatted payback summaries retain their values.
- Reuse `src/lib/money.ts`: exact safe-integer decimal conversion and bounded BigInt parsing. Blank, exponent, negative input in nonnegative fields, overprecision and unsafe values cannot form a valid request. Negative existing amounts can be formatted for read-only history; no new refund capability is implied. Integer minor-unit API/storage contracts remain unchanged.
- The dollar input retains partial/invalid raw text visibly and signals invalidity; it cannot create an API request or recovery envelope until the existing request validator accepts all fields. Calculated awards update dollars and cents together. Pending operations remain locked to their original cent payload/key on retry.
- Setup estimated expense entry uses dollars; member/print prize summaries remain dollar-formatted. Human-facing Side Pool CSV columns now say USD and contain decimal dollars. This deliberately changes the downloadable display/export format, not underlying data or API. No repository consumer of the old cents-column CSV was found; external spreadsheet consumers must account for the explicit header change.
- Fresh activated structured-schedule events with no legacy history enter canonical playoff outcomes from the legacy workflow entry route. Existing legacy records stay readable; unavailable reads do not cause automatic reclassification. Existing canonical outcome/V5 draft routing remains unchanged.
- Payback receives the exact source reference from the version actually bound to its draft, not the latest setup version. It displays that reference read-only and explains its exact-match requirement. Existing saved reviews and retained requests take precedence; no retry payload is silently replaced. The official ACC source is still separately reviewed.

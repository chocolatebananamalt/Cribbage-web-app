# Truthful synthetic scorecard evidence — local implementation, 2026-10-30

## Purpose and acceptance

The hosted rehearsal stopped at 15 verified games because its next operation would have asserted comparison of original physical paper cards that did not exist. The denied hosted operation was not retried. This feature instead provides actual generated, downloadable UTF-8 test scorecard artifacts, paired by game and participant, with immutable hashes and an explicit statement that no physical original or human review is claimed. Generated artifacts do not become physical originals by being printed or downloaded.

Success means: an explicitly authorized staging fixture can use the ordinary two-entry scoring machinery with truthful provenance; unknown or production deployment, unauthorized fixture, missing artifact, forged reference, stale version, revoked official, inconsistent re-entry and alternate scoring paths fail closed. Ordinary production paper requirements remain unchanged. Exact historical accepted receipts remain recoverable and are never retroactively given synthetic provenance. This is software acceptance, not physical-paper, independent-human, camera or field/offline certification.

## Design and security boundary

- A strict server predicate requires the exact staging Supabase URL `https://nnhcnvksxgxnpvdqjgpg.supabase.co` and an explicit Preview or known development/test runtime. Production, unknown and missing runtime states do not enable the feature. A URL parameter, tournament name or client flag grants no authority.
- Database enrollment is independent: private immutable deployment authorization, exact event/tournament enrollment and paired artifact rows. The migration seeds **no** deployment, fixture or artifact. There is no application/service RPC for enrollment or artifact preparation. A later separately approved staging operation must verify the project through the connected platform, then insert the narrowly reviewed enrollment and generate the disclosed plan with the owner-only helper. The deployment row is an administrator-controlled authorization record, not a database self-discovered proof of its Supabase project identity; runtime/backend verification and platform preflight are both required. Do not restore staging authorization rows into production.
- Four private forced-RLS tables: `synthetic_paper_deployments_v1`, `synthetic_paper_fixtures_v1`, `synthetic_paper_artifacts_v1`, `synthetic_paper_provenance_v1`. No direct browser or service-role table grants. Supporting FK indexes and immutable triggers are included.
- Three new public service-role-only RPCs: `get_synthetic_paper_evidence_v1`, `complete_synthetic_paper_game_v1`, `review_synthetic_paper_game_v1`. Artifact preparation is private and owner-only. Backend routes derive the actor from verified authentication and enforce same origin, exact payloads and exact scope.
- Generated text binds tournament, event, canonical game/version, side, participant/opponent, Verification ID, winner and spread. SHA-256 values are generated from the stored UTF-8 text. References contain artifact ID, side and hash. The insertion guard recomputes the expected text from canonical identities, so a forged manifest/text cannot be inserted as an authorized artifact. No image bytes, credentials, private photographs or external OCR service is added.
- The wrappers call the existing capture/review writers, preserving official identity/nonplayer checks, role checks, game versions, reciprocal claims, independent re-entry, operation hashes, canonical scoreline creation, locks and receipts. Current one-official policy is retained; the UI does not claim a second human. Append-only provenance joins each accepted operation to its exact artifact/hash pair and records `physicalOriginal=false`, `humanReviewClaimed=false`.
- An enrolled event fails closed for new ordinary captures **even when its artifact is missing**. Alternate submission/confirmation, recovery, hybrid, correction/projection and canonical scoring updates are guarded. These new restrictions apply only to explicitly enrolled events. The synthetic path does not support corrections or another evidence mode after enrollment; a future correction workflow requires its own reviewed provenance design.
- Enrollment locks tournament, event and games before testing idle state. Only clean paper-only Standard Singles fixtures are supported. Pending legacy reviews, any ordinary/independent correction history, unresolved scoring/recovery/hybrid work and finalized qualification prevent enrollment. Enrollment must occur in a separately verified quiet staging window; the two paper-writer lock races do not prove arbitrary legacy digital/correction writer concurrency or a general live-event migration protocol. Previously approved captures remain unmodified; exact receipt replay does not insert and remains valid. No legacy pending review is silently converted into a synthetic comparison.
- A narrowly asserted repair aligns the existing capture receipt-reader's role lookup with migration 0223, which already permits director/co-director capture. Its actor/tournament/operation/target, current identity binding and independence checks remain unchanged. No new human grant or wider arbitrary receipt reader is added. This existing-function change must be included explicitly in any rollout approval.
- Synthetic UI suppresses physical photo controls and stored-photo links, uses synthetic per-side labels, exposes the actual artifacts and hashes, and keeps capture and re-entry inputs separate and initially blank. Missing artifacts show a blocking message. Normal-mode original-paper comparison wording is unchanged. Unresolved recovery envelopes retain actor-scoped identity and use exact-operation reconciliation across reload.

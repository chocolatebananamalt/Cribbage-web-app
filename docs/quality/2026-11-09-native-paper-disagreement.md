# Durable independent paper disagreement — private candidate

Acceptance: an assigned independent nonself reviewer can retain what they actually re-entered when it differs from a consistent saved paper capture. Both records remain immutable. Neither is treated as the winning score. The game must remain blocked until the existing audited Director reopening and fresh independent verification succeed. The change must preserve blind digital entry, exact retries/recovery and historical evidence.

## Implementation

Reuse the existing paper-review evidence/receipt/audit envelope with an explicit `disputed-simulation-only` decision. Accepted reviews still require equality; disputed reviews require actual inequality and the complete original set of paper sides. Capture/artifact/game/source bindings, current reviewer role, separate actor and nonself identity checks remain authoritative. No extra score, winner or approval is inferred.

Fresh independent fields remain blank. A valid disagreement presents Record Disagreement, with a clear statement that both records are kept and the game is blocked for Director review. The saved request retains the exact independently entered values and original capture/artifact references. Subsequent actions cannot overwrite it or confirm the capture. The Director workspace displays the capture and disagreement separately; reopening chooses no winner and uses the existing source/history-pinned, reasoned, nonself, policy-zero workflow.

In DP games, paper review can precede the digital player's own entry. If the current game has a bound disagreement, its own-player metadata-only state reports `playOrder: review`; no hidden entries or values are exposed. The player sees a read-only review block, cannot submit/confirm and retains that same current game on the scorecard. Future games remain upcoming. Old clients fail closed on the new status. Deployment must coordinate the new closed append gate and compatible clients; this is not permission to enable either.

The separate SQL delta replaces six private functions and adds one literal-false private gate. It adds no table, RPC or grant. The previous verified correction SQL remains unchanged. The new gate blocks fresh disputed writes only; accepted historical proof/recovery remains valid with the gate off. A valid disputed request encountering the closed mode receives the specifically scoped `retry_exact / paper_disagreement_unavailable` result only after role/source/history/full-claim checks. Its exact saved copy remains available for checking or an explicit retry; nothing is cleared or sent automatically. This avoids stranding an attempted request behind a feature switch and does not authorize a score.

The delta depends on the prior local correction proposal; it is not a standalone update for the existing hosted schema. Old clients fail closed on new disputed evidence/review metadata. Rolling back to older function bodies after any disputed record exists could invalidate historical proof, so a future rollback must keep compatible recovery readers and disable new writes rather than erase records or blindly remove the functions.

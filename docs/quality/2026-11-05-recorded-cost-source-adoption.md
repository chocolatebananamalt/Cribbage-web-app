This adoption slice adds no mixed-play authority; existing native playoff and final-recipient guards remain responsible for that separate scope.

- Browser checks: phone/tablet/desktop, 200% text, keyboard, stale callbacks/source changes, single expense selection and retained typed choices. Durable pending requests must retain exact scope and operation bytes; unknown outcomes are not successful saves.

## Deliberate v1 limits

Adoption uses existing recorded expenses and reviewed allocation writers. It does not create expenses or silently allocate them. Existing native-cost corrections, removals, classification changes and ambiguous many-to-one/one-to-many replacements remain blocked. The old proposal must have no unfinished line/band form. Qualification/settings/entry-receipt frame changes are separate work.

The fee selection is local review intent until a fresh post-adoption recorded-fund review is accepted; it is not part of the adoption's twelve-key request and does not prove payment or remittance.

An existing, separate expense screen was found to clear other actors' recovery keys on mount and retain only digest/recovery identity. It has not been changed in this slice; its recovery behavior must be corrected or excluded before enabling cross-account expense-entry navigation. The new recorded-cost component does not mount that screen or perform its cleanup.

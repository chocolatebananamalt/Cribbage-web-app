# Paper-photo text retention and recovery: private candidate

The manual photo aid now has explicit **Save Text Draft**, **Check Saved Text Draft**, **Restore Saved Text**, and confirmed **Remove Active Saved Text** actions. This uses the existing native pending IndexedDB port with a separate text-draft key family, not the evidence writer. Nothing autosaves, resends, records a score or approves a review. No photo, file, object URL, player name, session ID, acknowledgment or confirmation is persisted. Saved cells may be incomplete and remain an unverified proposal.

The current native host supplies the existing retained port and a validated card/source scope. Keying includes project origin/ref, account, tournament/event, game, paper side and capture/review phase. It deliberately excludes the source head/revision so obsolete raw data is found and held. The stored scope also pins Start/source digest, participant/fixed Tournament IDs, game number, official identity binding, capture ID, revision and history digest. A changed native source remounts the photo aid. An independent reviewer has a separate account/phase key and starts blank.

Read/check never fills fields. Restore requires a newly selected photo, exact current scope and current host admission, and resets photo confirmation plus the native independent-entry acknowledgment. A valid new session for the same account can recover matching text after fresh host admission; the record does not establish any historical-session authority. The human must compare the photo and values again before copying one paper side into the normal form.

Updates compare exact previous bytes and atomically archive the replaced known record. Each local version has a noncredential random identifier so a remove/new-draft cycle cannot collide with an earlier archived revision. Removal deletes only the active known matching copy; archived text remains. Unknown, oversized, future, foreign or stale records are never filled, overwritten or deleted. A stale held draft currently cannot be replaced through these controls; the normal manual paper-entry form remains available. This is a deliberate fail-closed limitation, not a new user-policy decision or permission to clear browser data.

Concurrent writes fail with an explicit conflict; checking storage is required before retrying. Admission loss, abort, thrown read/write and uncertain committed response invalidate cached restore/save/remove state without deleting or rewriting stored bytes. Unmount/revocation aborts a transition that has not committed; a fresh check reconciles any already committed result. No old operation resumes automatically.

## Verification and correction

Ten pure storage/controller groups pass, including partial text, two-tab exact-byte conflicts, archive/remove/new-cycle, stale source/identity isolation, unknown preservation, abort-before-commit, uncertain committed response, same-account new-session context, and permission-loss races. Existing manual/OCR/paper scope/nonself groups remain part of the focused check; OCR provider calls are injected mocks only.

Independent review found a P2 during implementation: an in-flight committed save/removal or failed read across admission loss could leave an earlier cached draft available when admission returned. It did not overwrite stored bytes, but incorrectly allowed cached Restore without a check. All post-await failure/admission exits now clear cached record authority and mark storage unavailable. New delayed committed-save/removal/throw and read-error regressions require explicit check before recovery resumes.

Actual offline React with the native paper host passed at390/1440 pixels and100/200% text. It used an injected transactional CAS port and a synthetic one-pixel image. It exercised explicit save, host remount, fresh-photo requirement, no restored confirmation, no automatic field fill, simultaneous-host conflict, explicit check/restore, archived removal/new cycle and blank independent reviewer. Zero network/transport writes. This is **remount/controller proof**, not browser disk persistence or full reload.

A separate probe used the unchanged real IndexedDB adapter on the existing supported `about:blank` surface. The adapter reported storage unavailable when opening the database. The probe stopped without changing origin, security settings or using a denied navigation. Thus real IndexedDB/full-page-reload acceptance remains **unverified**. The UI retains its explicit storage-unavailable message and cannot promise retention there. This is the exact remaining environment/provider-device acceptance gate; it is not a need for another PostgreSQL fixture or 108-game run.

Evidence: `test-results/paper-photo-text-recovery-20261109/` (initial31 focused groups, final10 recovery groups, browser result/screenshots, IndexedDB probe result, TypeScript/lint and source manifest). Final TypeScript and scoped ESLint pass. Earlier TypeScript checks caught missing types and an over-specific cast in the generated probe entry, not product source; a typed `Object.assign` declaration corrected the harness without changing probe behavior. Failed logs remain retained. Independent source review verified the admission-loss correction and found no remaining P1/P2 issue. The new flow is not enabled on hosted systems. No images were transmitted, live OCR enabled, SQL run, permissions granted, real funds used, or interrupted publication retried. No full application/build/rehearsal simulation was repeated for this bounded change.

## Smallest later device check

This client-only addition requires no new PostgreSQL migration or repeated tournament simulation. Once a separately approved preview/cohort is available on its normal HTTPS origin, the narrow acceptance check is: explicitly save one fictional text row; reload; choose its photo again; restore and verify that confirmation/acknowledgment remain off; switch to the independent reviewer and verify blank isolation; then test one two-tab conflict and explicit recheck. Do not record a game as part of that text-only check. This plan does not authorize access/release or override the recovery commitment for a broader write-enabled trial.

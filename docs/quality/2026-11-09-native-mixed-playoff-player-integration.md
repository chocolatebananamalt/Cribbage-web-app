# Native mixed playoff player integration: private checkpoint

This is a default-disabled local implementation, not a hosted release or a
claim that Daron's human rehearsal is ready. No additional hosted records,
grants, credentials, deployment or money movement occurred in this checkpoint.

## Observable behavior

The player screen now has a normal authenticated-client transport, exact
retained-operation recovery controller, browser host and private server route.
The route pins the configured test project before SDK construction, checks
the actual cookie identity around the own-player RPC, and passes only its
authenticated scope to hydration. Result data is fetched again under the
browser's current identity before display; the server result is not passed
as a browser-visible initial result snapshot.

The host synchronously hides private content on authentication invalidation.
Its per-host admission tuple also prevents a subsequent React render from
revealing stale content. Session, target or retained-port replacement invalidates
old asynchronous work. A command is generated only by an explicit permitted
action, retained with compare-and-swap before dispatch, and never silently
rebased or redrawn. A receipt alone does not mark the game verified: the exact
operation is archived and cleared only after fresh matching own-server proof.
Unknown outcomes and rejected-source history preserve the original operation.

Normal own-playoff RPCs were already proved against the second disposable
fictional PostgreSQL fixture, including opponent-first blind-entry behavior.
That fixture and the first fixture were independently confirmed removed. The
new browser host does not create or retain a database fixture.

## User workflow and recovery

Names and stable Tournament IDs identify both opponents. Each paper card has a separate required blank winner field and independent-reading acknowledgment. Differing PP readings are preserved. Changed head metadata retains unsubmitted choices and requires explicit review/reset; it never silently rebases them. No ACC number, table or seat substitutes for identity.

The normal SDK provider checks exact environment, actor, session, issuer and expiry. It never calls the administrative getter. Offline entry is permitted only under a previously verified, unexpired session lease; the exact request must be confirmed in retained storage before any send. Reconnect never resends automatically. Unknown/other-session work is hidden and preserved. Lost acknowledgments require bound accepted/superseded/absence-closure proof and atomic archive before clearing. Rejection, stale source, storage contention, mode-off and uncertain responses retain the original request. No replacement nonce or matching answer is fabricated.

Independent review caught a busy flag published before being reset during auth/expiry/transport revocation. The narrow ordering fix keeps private content hidden and Check Session usable. Actual development StrictMode Host tests hold an RPC open, revoke the session, check recovery controls and release the old RPC without reopening content; a second case loses identity in the transport without an SDK auth event.

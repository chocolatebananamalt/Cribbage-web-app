# Q Pool membership and receipt allocation - local implementation

## Scope and source

Owner approved local implementation/testing on 2026-10-28: explicit opt-in, named-pool allocations, full payment for paid-entry status, ordinary entry locked at Start Play, reasoned director corrections, automatic payouts disabled. These are approved app defaults; do not call every detail an ACC mandate.

Official ACC Director Manual, February 2019 edition, section 8A, printed pages 12-13 (fresh official PDF read 2026-10-28): Q Pools are optional and separately funded; the director selects the payback method, discloses it before entry/payment and on the flyer, announces participation before play, and distinctly identifies entrants' scorecards. Equal and graduated approaches are discussed, not one universal percentage formula. Source: https://www.cribbage.org/NewSite/sched/Directors%20Manual%20-%202019.pdf. This slice warns about disclosure but does not certify it happened or generate a payout method.

## Implemented contract

- Private director/co-director page and same-origin verified-subject API. Every configured pool version is explicitly elected or declined; opt-in requires a consent evidence reference. No membership is inferred from old CSV dollars, receipt amount, account identity or playoff finish.
- Membership is one immutable, contiguous per-roster/event versioned snapshot containing the exact complete configured pool-version UUID set. A snapshot changes all affected pool choices atomically; old consent and reasons remain retained.
- Separate immutable allocation snapshots bind exact membership version, current cumulative receipt UUID, obligation version and activated base-fee event version. The director explicitly allocates base plus each named pool; no priority or rounding is invented. Every line is capped by its configured/elected fee, declined pools get zero, and all lines sum exactly to the current receipt. The current obligation must equal base plus elected Q fees. No obligation, receipt, refund or actual payment is created by this page.
- Elected, owed, allocated, source-current and paid-entry status remain distinct. Base and the relevant named pool must be fully allocated for that pool's paid-entry status; another elected pool may remain partial. Paid-entry status is not qualifying/payout eligibility. A changed/voided receipt, changed obligation/membership or unsupported context makes funds stale/ineligible until a reviewed replacement snapshot; history remains immutable.
- First safe allocation scope: exactly one event and one setup activation, active Standard Singles Main, one or two positive-fee Q Pools, no Side Pool history or other event/fee domain. Even a retired second event is blocked because old cumulative cash could include it. Existing event enrollment and an active roster/participant are prerequisites. Unsupported contexts render clearly, not as a successful empty ledger.
- Pre-play ordinary changes: director/co-director. Corrections: director and recorded reason, with an existing record. After Start Play, only pools with immutable pre-play election evidence can be corrected/restored. First late opt-in and first late allocation are blocked pending policy. A post-start allocation correction must reuse a receipt already bound by a pre-play allocation; legacy receipt `recorded_at=now()` is not trusted as proof of actual insert time. No legacy timestamp default changed.
- Current role checked before exact replay. Tournament no-key lock serializes receipt/obligation/start writers; roster and participant no-key locks preserve active-status validation while remaining compatible with attendance FK checks. No attendance advisory lock inversion is added. Exact success and known-rejection receipts reconcile; changed same-key requests conflict; stale version writes do not append records.
- Retained UI requests use `payment-obligation:q-pool:<actor>:<tournament>` under an already shipped recovery prefix. Older bundled account-switch counters recognize it; ordinary amount-owed writers cannot collide with this namespace. Singleflight, unknown outcome retention, exact-body/key retry, newer-storage preservation and coordinator guards remain intact. No protocol/worker/auth-policy change.
- New director navigation link; USD dollar labels/inputs and integer minor-unit storage. Automatic Q Pool payout, canonical settlement Q claims and legacy recalculation remain disabled/unchanged.

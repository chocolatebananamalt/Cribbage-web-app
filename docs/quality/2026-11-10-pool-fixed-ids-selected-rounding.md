# Pool Tournament IDs and selected-rounding proposals

Fixed-ID Results implementation is complete locally: the native pool Results reader requires an immutable initial-seating publication with its accepted, actor/tournament/target-bound publication receipt. Each award participant must join through this event's roster entry to that publication's assignment, and its fixed ID must equal the participant's starting `table_seat`. Missing publication, receipt, mapping or ID holds the entire view. The decoder rejects duplicate/conflicting participant-to-ID mappings across pools. No name or ACC-number match is used. Existing award rows are untouched.

The Results view now shows captured names and their verified Tournament IDs instead of the prior missing-ID warning. The wire contract requires the seating publication ID server-side; it is not rendered. Existing Main/primary-Director scope, no-refund policy and current qualification pin remain.

Built the next selected-rounding accounting slice:

- `selected-step-pool-amounts-v3.ts` implements the reviewed exact Equal-Q, raw-weight Graduated-Q and verified Sheet Side models with $1/$5/$10 increments. It conserves each pool separately using exact rational/largest-remainder arithmetic. Inexact Equal shares, non-divisible funds, unsupported fee tabs, one-recipient Sheet ambiguity, floor/order failures and unknown methods remain blocked. No remainder refund or method switch is invented.
- `selected-step-combined-accounting-v3.ts` builds a **proposal**, using the existing saved-prize/current-ledger basis validator. Q and Side increments come independently from the saved prize plan, not a caller-selected numeric override. Retained/current pool-review inputs must match, carry the qualification/review/version pins, and match the ledger's exact separate pool funds. Recipient identities must be paid and consistent; Equal Q includes every paid playoff qualifier. Missing pool fund coverage holds. Regular-prize estimates and their imbalance remain separate; pool money is not used to cover them.
- This is a new proposal version. It does not relabel existing $5 records, silently adopt an old policy, invent recipient order or grant financial authority. A new explicit selected-step policy tag is required. Current source/recipient-order verification is still the authenticated collector's responsibility.

Known independent examples for 17 paid entries of $10, ratio 6: Q proposals are $85/$57/$28 at $1 and $80/$60/$30 at $10. Sheet Side proposals are $93/$57/$20 at $1 and $90/$60/$20 at $10. Each totals $170. Equal Q with five recipients gives five $34 awards at $1, and holds at $10 because an exact equal split is impossible. The combined fixture binds Q $1 and Side $10 while preserving its separate $1,800 regular fund and two $170 pool funds.

Checks: nine pool Results groups and five selected-rounding/proposal groups pass; TypeScript and scoped lint pass. Independent source review found no P1/P2; a narrow ledger-projection call was corrected during focused checks. Existing UI/controller checks were reused rather than running tournament simulations.

**Remaining implementation gate:** selected-rounding proposals are not mounted into a native authenticated collector, durable journal, finalization or Results producer. Their source pointers and recipient-order reviews cannot be treated as live proof. The current $5 journal's constraints remain unchanged and must not receive these proposals. A versioned source/save/finalization bridge is still needed for operational $1/$10 combined accounting. This is unfinished implementation, not a missing owner policy or permission. All source flags explicitly deny current-source, write, finalization and payout authority.

No SQL execution, local database fixture, hosted read/write, permission change, publication or denied-operation retry occurred. All existing feature gates remain off. SQL/runtime/provider acceptance is still required for the fixed-ID query and any later journal integration.

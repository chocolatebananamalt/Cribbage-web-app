## Parser safeguards and registration binding

The parser rejects unresolved/dynamic names, parameter forwarding, nonconstant/forward/destructured argument bindings, computed keys, methods/getters, object mutation/escape, cyclic/excessive indirection and unsupported SQL declarations. It counts generic and statically computed RPC access, detects escaped/destructured methods, and ignores text in comments/strings. Argument objects passed to unknown functions or stored in containers are conservatively unsupported. This is bounded static analysis, not whole-program JavaScript verification.

Finite name and argument branches are cross-product checked. Identical condition text is not assumed stable. Only a shared lexical const with an initializer that guarantees a primitive boolean may correlate decisions. Regressions cover changing/effectful conditions, mutation through aliases/functions/containers, computed destructuring, malformed syntax, missing signatures, changed pins and unsupported shapes. Unsupported forms stay audit failures.

Registration now captures one validated-JSON property-presence boolean and uses it for stationary admission, the selected RPC and the optional stationary argument. Explicit `stationarySeatRequested:false` still counts as present. Credential parsing, redemption material, digest, actor/receipt binding, response handling and other guards are unchanged. The actual-route regression proves the two finite target/key combinations. This avoids relying on three separate property lookups to establish one dispatch decision.

## Remaining blockers and deployment implications

Stronger scanning exposes 24 opaque forwarding sites and additional finite named RPCs. The final inventory records 17 additional names with proposal-only definitions, and 46 unresolved declaration records including branch variants and opaque targets. These were not inspected by the former literal-name regex. No unknown-name exceptions were added: the parser-coverage and declaration-coverage assertions remain red. Forwarders need finite interprocedural provenance of both target names and argument objects from every production entry, or a runtime dispatch boundary that validates literal names and shapes. Erased TypeScript union types alone are insufficient. The additional named proposal contracts need independent caller/gate review before source resolution; proposal presence does not establish installation or permission.

The exact original-call classification and expanded function/file/signature inventory are in `rpc-audit-evidence/function-inventory.json` beside this candidate; raw call records are in `expanded-call-inventory.json`. The reviewed source inventory is also retained separately. No backend was invented and no application test was silenced to clear these blockers.

The final complete application run executes 3,605 tests: 3,603 pass, 2 fail, zero skips. The two failures are the expanded RPC parser/declaration coverage checks. Targeted parser/source-contract/MRP/stationary tests pass 30/30 with zero skips. The final handoff manifest records the post-change typecheck, lint, standard build and workspace results and their actual command logs. `pnpm verify` is unavailable on PATH; individual commands are executed directly. Passing source checks does not certify deployed availability, actual provider sessions, ACC acceptance or all 15 integrated functions.

# Snapshot-bound event play closure

## Implemented locally, default off

Existing migration 0229 already implements explicit Close Event, unresolved scheduled-game checks, immutable play-close history, audit and restricted reopening. It is a play-entry closure, not payment, ACC reporting or tournament-wide completion. Legacy `event_play_state_v1` derives `finalized` only from legacy settlement finals. Changing that reader to recognize the modern snapshot would change `playState: completed` values already captured in the modern pool proofs and immediately invalidate their source digests. This implementation deliberately retains that sporting-state derivation.

`database/proposals/modern-event-closure-v1.sql` connects the existing Close Event lifecycle to the actual current approved modern snapshot. A separate explicit Director confirmation pins snapshot ID and current source digest; live primary-Director/session authorization and the existing scheduled-game readiness predicate are rechecked. The transaction calls the real `public.close_event_play_v1`, or binds an already-closed event, verifies its actual latest closed row, then revalidates the current snapshot before appending the immutable closure association and audit. Failure rolls the original lifecycle mutation back. Exact accepted retries recover their historical result without relabeling it current. Scope is one event; other tournament events are untouched. No reopening, cascade, refund or new payout policy is introduced.

The existing default-off final-review transport and Director page now offer this separate stage after pool and unified unpaid approvals. Retained exact requests use the same actor/event ownership and recovery path. Closure has an additional literal-false gate, independent of earlier approvals. A closure request is not interchangeable with a pool or final-approval request. Original history is preserved. Unknown/rejected retained requests are preserved rather than silently discarded.

The visible lifecycle is truthfully `closeState: closed`; this does not claim that the legacy `playState` has become `finalized`. It blocks play using the existing lifecycle mechanism and retains its original API-enforcement limits. Awards remain unpaid, proposed MRP remains proposed, and membership/API uncertainty or unresolved registration overrides add no report gate. All code remains local/default off; frozen216, hosted services, publication and real submissions/payments were untouched.

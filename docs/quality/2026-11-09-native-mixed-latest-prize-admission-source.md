## Observable scope and stop condition

The new `native-mixed-latest-prize-admission-v1.sql` is a read-source adapter,
not a prize calculator or ordinary Finance bridge. Its opt-in domain is one
informal Standard Singles Main, twelve qualifying games, eighteen fictional

Success at this checkpoint means source dependency/identity checks pass and an

## Preservation and actual dependency path

The installer hashes normalized recoverable `pg_proc.prosrc` bodies against the
exact current source bodies, and separately checks owner, language, security,
return type, volatility, search path and UTC configuration. It copies the
actual installed full definitions to revoked legacy functions. It does not
rename the original functions: `CREATE OR REPLACE` retains their OIDs, checked
after replacement. The legacy copies keep their original body and metadata.

For tournaments without any latest-prize history, dispatch returns the legacy
function's output and digest domain unchanged in the supported READ COMMITTED
flow. Latest snapshot/binding/pin history, including a missing or stale head,
is a barrier: disabled or invalid latest input never selects dormant V1. The
presence check reserves the latest setup/prize sources; unsupported isolation
fails closed rather than extending the original transaction contract.

The latest branch reuses `event_prize_activation_current_v1`, then binds the
actual operational binding, activation, event version, settings snapshot,
revision binding, current prize head/snapshot, full accepted save record and
operational outcome. The exact plan, settings and activation captures enter
`latestPrize`. Only the old payout-factor assessor is replaced with the
existing series-only assessor, through unique pinned anchors. No neutral V1
declaration, ordinary receipt, ordinary Start or fake native allocation ID is
created.

The existing funding scope stores `baseSource` in full, and the entry/current
funding proofs compare the complete base capture. Attendance binds that funding
source; its seal is compared in the existing game-root/Start proof. Thus the
latest pin participates transitively in their digests without changing their
tables or writer request contracts. The native playoff source receives the
same narrow versioned assessor/capture adaptation. Source inspection found
only the admission and native playoff source using the old assessor in this
native family. Browser funding/attendance/Start DTOs expose summaries and
digests, not an exact-key copy of this internal base object, so no TS DTO change
was needed.

The captured plan explicitly says `latestPolicyExecuted:false`. Existing
manual simulated Main Finance remains a disclosed manual path; this adapter
does not turn it into execution of the saved Graduated/factor/rounding policy.
Ordinary `new_prize_accounting_required` and
`new_prize_playoff_integration_required` guards remain intact.

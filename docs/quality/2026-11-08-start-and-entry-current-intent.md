## Reproduced defects

Actual offline React reproduced Start submit(true) after a captured enabled
handler's checkbox was unchecked. Digital Submit after Clear and Paper Record
Independent Review after acknowledgement revocation each allocated one ID,
performed two memory retention transitions and sent one MOCK transport write.
These are UI-intent defects, not proof of backend authorization bypass. Baseline
artifacts and original Digital/Paper source snapshots were preserved.

## Changes

Start dispatch binds current activation/controller/context, canonical full
request and current cloned snapshot, online status and stage. Acknowledgement
is bound to the whole request, not just operation ID; a changed body reusing an
ID does not retain consent. Synchronous revocation blocks held callbacks before
React commits. Flight ownership prevents duplicate clicks and old completions
changing a replacement panel's busy state or message. Disabled entry has no IO.

Existing recovery distinctions are preserved: allowPrepare gates fresh readiness
and initial submit; retained pending not_sent/retryable requests may retry
exactly without a new checkbox. Attempted requests remain check-only. Pending,
blocked and resolved requests can be checked when online, even when fresh
preparation is unavailable. No second Start nonce is generated by the UI patch.

Digital and Paper authoring now separates a current owner/source/snapshot lease
from local form intent. Edits/Clear/revoked Paper acknowledgement synchronously
invalidate old record callbacks before any ID factory. Fresh offline Digital
submission can still retain without sending; confirmation and Paper recording
require online state. Pending Send/Check/Resolve use their current lease, not
unfinished form validity or acknowledgement; old A callbacks cannot act on a
later B request. No-op Digital inputs leave the valid intent usable. Controllers,
transport formats, result calculations, source guards and persisted bytes are
unchanged. Unknown pending data is never silently removed.

## Implementation

- Exact request validation accepts the original five fields or those fields plus delivery=email/copy_link. Email is the backward-compatible default.
- `setup-official-delivery.ts` shares canonical nomination and existing delivery recording. Copy-link skips both OTP and delivery recording, leaving pending unchanged. The legacy internal `official_pending_email` sentinel precedes delivery and is never represented as sent mail in copy-link mode. A reader-availability preflight fails before the nomination write when local0238 is absent during rollout.
- Primary-director setup UI offers email or private link, can reopen pending handoffs after refresh, clears stale displayed links when saving/removing/changing delivery, retains input on errors and blocks simultaneous requests. Pending means Awaiting secure acceptance; an actual delivery failure remains distinguished. No raw invitation secret is returned or placed in the URL. Nomination UUIDs can appear in access logs; they are not bearer credentials.
- The public invitation page handles missing/broken sessions with the existing nullable current-subject helper and preserves the safe invitation return path through password/OTP sign-in. The server loads authoritative context, not spoofable query text. No-store authenticated GET reconciles lost responses; accepted rows for the same exact account remain readable after the invitation deadline. Pending acceptance still expires normally. Legacy long-secret acceptance APIs are unchanged; uncertain legacy results give honest Your Tournaments/reload guidance rather than a nonexistent context lookup.
- Local-only migration0238 adds one read-only SECURITY DEFINER function with empty search_path, qualified names, service_role guard and execution privilege only for service_role. It reads exact-email pending/unexpired or active/accepted-by-this-actor context and returns only status, nomination UUID, tournament name, role and original deadline. Missing, wrong-email, removed/expired and active-for-another-actor all return null. No existing function, role grant, lifecycle, acceptance mutation, audit or expiry guard is changed.

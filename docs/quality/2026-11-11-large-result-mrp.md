# Larger Native Saved Results to Proposed MRPs

Local/default-off source implementation. No SQL execution, database fixture, hosted change, grant, public upload, actual award/submission, or denied-operation retry. Frozen 216-file package unchanged.

## Added capability

The ordinary source-backed proposed MRP Results/CSV path now consumes saved native digital championship playoff results for 6–64 qualifiers in Standard Singles Main or regular Consolation. It automatically derives actual recorded main-bracket match wins and separately evidenced byes, then reuses existing published Main/Consolation MRP arithmetic. Qualification scores/ranks and fixed Tournament IDs stay bound to the current qualification version, live standings and trusted current seating. No membership/API/unresolved-registration-override gate, ACC/ZZ generation or actual award is introduced. Incomplete sporting proof leaves qualifying proposals with pending playoff/total values; changed qualification/identity/fixed-ID evidence holds the report. Extra/backward matches cannot create additional MRPs.

The missing dependency was that the existing native saved-game verifier and producer required a Finance proposal. The implementation extracts the sporting replay into one shared verifier, reused by the existing Finance wrapper and the new MRP adapter. All submission/amendment/own-confirmation lineage, distinct action/operation/submission IDs, game completion, settings/generation/parent result pins and chart-path checks remain. The Finance wrapper retains its old strict financial draft admission and computes the same full-envelope hashes. Six recorded pre-extraction outputs/digests (Main4/5, Consolation4 and 6/8/64 qualifier cases) are byte-equivalent after refactoring.

A new UNEXECUTED, revoked, default-false normal-auth SQL reader captures sporting evidence without a Finance proposal, ledger, pool or payout dependency. It derives the live user/session and actual Director/Co-director, pins latest/current qualification and operational settings review, and copies the existing verified player/generation/action/confirmation/game capture block unchanged. Existing completed-result verification and locked current-source helpers remain the authority for receipt/audit proof. SQL access is rechecked after capture. No new persisted records or write API is defined.

The ordinary reader requests this source only for 6–64 qualifiers, rechecks actual session/role around matching captures, and binds the producer actor/session, tournament/event/kind, qualification version/count and current participant/fixed IDs. The source hash and observed time remain in Results/CSV. Double reads do not claim atomicity. Known synthetic context is validated and explicitly labeled Simulation Only; malformed context holds. Absence of a synthetic marker never establishes physical play or independently verified humans.

## Scope boundary

This is result-reader/calculation coverage, not a new bracket generator or blanket approval of a hosted tournament. It reuses the existing reviewed literal chart/slot helper through 64 and changes no seed ordering, qualifier selection, generation writer, series winner rule or ACC award policy. More than64 qualifiers remain blocked for this path. Only fully evidenced native digital series are supported; paper/mixed uses its separate already-built five-qualifier rehearsal reader. Satellite/teams and missing source evidence remain separate/held. ACC references remain explicitly uncollected by these readers; points are proposed/hypothetical, not actual awards or ACC acceptance. Official event/player reconciliation is separate and absence remains pending.

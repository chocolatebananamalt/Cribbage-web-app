# Side Pool setup intent: local verification

Scope: the owner requested a payout-type dropdown and optional separate name, preserving Side Pool ranking by paid entrants' event scorecards. This local work is uncommitted and unpublished. No hosted database, user draft, real payments, permissions or credentials were changed. Equal/equal-double Side choices are visible but disabled pending an explicit supported policy; the graduated choices are 1-in-4/6/8/10, with a positive $5-increment entry fee. A choice is draft intent, not disclosure, collection, an award or a frozen policy.

Migration 0275 (`SHA256 7296e30b361deaf8d0334e0adaac442626c5ab7eef25a3fea70c45e5c10af2b0`) stores a nullable type only on new immutable Side setup versions, never infers one from historical names, copies it across unchanged amendments, reads it back, and binds the later graduated policy to the selected ratio. Existing fixed-policy writer cannot bypass a new typed choice. New typed selections are limited to supported Standard Singles; unchanged historical team pools remain readable/editable.

Setup and amendment APIs bind a digest of the complete request before the existing core writer strips Side fields. The configure function verifies actor, tournament, operation and event digest from the accepted core revision. Changed retries fail; unresolved pre-rollout core-only Side writes with no binding fail closed. The browser retains the original request, gives an actionable warning, disables retry, and preserves the warning across reload using an actor-scoped recovery marker. Verified old Side configurations can be replayed unchanged without fabricating a type. Tournament/role/revision locks use the activation ordering.

App-first compatibility: only an exact `PGRST202` naming the new capability RPC selects old legacy-only setup behavior; any permission, transport, wrong-RPC or malformed capability response fails closed. Typed choices are unavailable until capability is verified. Existing pages read three-key historical Side definitions; an unchanged untyped Side can be carried to a new revision only against the authoritative matching prior version and same event kind/style/format/name/fee/note.

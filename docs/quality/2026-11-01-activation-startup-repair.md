# November 1: activation startup regression investigation

Phone reported "This activation link is unavailable" after both email-draft auto-link navigation and pasting the full matching URL into Chrome. Transfer truncation is not established. Read-only 08:45:36 UTC staging check showed activation e741b0fe-1764-4677-a11b-2129f4ea835b still issued, unused, not cancelled and expiring 09:03:37 UTC. Laptop URL host/path/fragment shape matched the supported generated format; no token was logged.

Production root cause reproduced locally with disposable data: /activate placed its beforeInteractive Script inside RecoveryDocumentBoundary. That boundary initially hides its children until client recovery readiness. The late Script registers after Next startup and does not execute, so a valid fragment produces the exact unavailable page. Without the boundary the same component accepts it. With the actual boundary and nonce-based script policy it rejects an intact token and leaves the fragment untouched. Installed Next16.4.2 docs explicitly require beforeInteractive in the root layout.

Narrow LOCAL fix: move activation bootstrap to root layout outside the unchanged recovery guard; restrict capture to /activate, preserving other URL fragments. Capture startup/client-navigation/hashchange values into memory only; clear bootstrap value on pagehide even before form mount. Form claims into a ref, survives StrictMode effect replay, handles a freshly pasted full link in the same tab, and prevents another submission once consumed. Pagehide/redemption/failure clear secrets; no local/session storage, credentials, server grants, expiry/replay changes or new endpoint.

Separate real-component development reproduction also proved cleanup during StrictMode effect replay destroyed the previous credential. This alone was not the production diagnosis. Local VM probes and real-component production/development harness outputs are under test-results and excluded from public/source backup as generated evidence. All tokens/profile IDs in harnesses are disposable synthetic values; mocked redemption only, zero live API requests.

Verification and independent review are in progress. No commit, push, migration, hosted new link or deployment is authorized or performed. The real phone link should not be retried against the known broken deployed startup path. Both sessions and all staged tournament/history data are preserved. Once local gates pass, request only the narrow test-preview publication; a fresh short-lived link will be needed if the original expires.

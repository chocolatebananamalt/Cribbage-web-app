# Event declaration check and pinned activation: local work

The local setup screen can check that every paid Main/Consolation declaration is current for the saved setup and that no retained request or conflict marker exists. Free optional events need no paid declaration. Unsaved declaration edits block this advisory check; the Director can save them or reload to discard them. The check rereads setup version/revision and declaration workspaces, then rereads recovery storage. Errors, stale settings, unknown payloads and unsupported events fail closed.

Independent review identified that a declaration version can change after a successful read without changing the setup revision. The local flow now checks the role-checked 0289 capability, captures the exact declaration IDs and settings fingerprints, rechecks them on confirmation, and sends those pins with the retained activation operation. The database atomically compares the pins under lock. Missing capability fails closed. This is a local implementation; no hosted deployment has been authorized, and financial accounting is not finalized by activation.

The declaration editor verifies exact recovery-storage readback before sending. A failed readback sends nothing. An idempotency conflict preserves the original request and a blocking warning across reload; it is not silently retried or cleared.

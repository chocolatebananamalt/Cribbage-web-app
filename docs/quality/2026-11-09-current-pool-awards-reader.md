# Current-source simulated pool awards - local work in progress

## Acceptance and scope

A current authenticated Director must be able to read the event's actual saved, unpaid simulated Q-Pool/Side Pool awards even when a different Director originally finalized them. A historical receipt must never establish current awards. Current funding, saved pool policy/rounding, sealed membership, verified untied qualifying review and persisted obligations must all agree. Missing/stale/unsupported information stays unavailable, not zero; a genuinely recorded empty pool is distinguished explicitly. Preserve normal results, original records, permissions and closed gates. No real liability, payment, refund, ordinary MRP or hosted operation.

## Source candidate

`database/proposals/native-mixed-pool-results-read-v1.sql` adds six private/default-off functions including one revoked public read wrapper. It replaces no function, adds no table and grants no access. Installation pins the original producer, saved-setup and calculator bodies/owner/security/config. Read proof reuses the exact original seal/final producer branches to verify existing values, rather than introducing another distribution policy. It validates historical operation/request/record/accepted-receipt/audit bindings and entity ancestry separately from current source authority. It does not claim historical author-session evidence that old records never captured.

Current proof checks the live actor/session/expiry/Director/cohort, event lock, unique actual Start, seal-before-Start and final-after-Start, current simulated funding and setup/rounding, terminal seal/final journal CAS points, exact reconstructed seal, current verified qualifying review, unchanged expected final payload and bijective unpaid-obligation records. It does not infer arbitrary historical journal order from timestamps. Output contains only the current reader identity, source pins, saved method/fund/rounding and recipient IDs/amounts. All money/liability/MRP/write-authority flags remain false.

The client accepts only this dedicated current response, binds it to the same event/actor/session/Start/review/funding/journal/seal and exact saved policy plus full funded election lists, checks sums/increments/identities, and joins names by stable participant/fixed Tournament IDs. It does not calculate or choose new recipients. The normal-auth Results adapter serializes the source readers and double-matches captures; that is a matching observation, not an atomic cross-section transaction. The UI marks all records Unpaid Simulated, separately lists each pool and distinguishes an exact recorded empty pool from unavailable data. Standard Main/Consolation/Satellite paths and access are unchanged.

PostgreSQL/Supabase function privilege/search-path guidance was checked against the current [PostgreSQL function documentation](https://www.postgresql.org/docs/current/sql-createfunction.html) and [Supabase database functions guide](https://supabase.com/docs/guides/database/functions). The markdown changelog endpoint was unsupported by the web reader; the official HTML changelog was read instead. No client/dependency upgrade is being made.
